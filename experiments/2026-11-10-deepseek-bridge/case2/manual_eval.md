# Case 2 — ручная оценка

Вопрос: «Какой статус у M сейчас?»
Допущено: `g-m-not-operational` — «M is NOT operational NEGATION-NOT-MARKER».
Исключённых записей нет.

## Граница отправки

В подготовленном теле и на проводе (совпали): есть `g-m-not-operational` и полный claim с `NEGATION-NOT-MARKER`. Нет маркеров L/stale/superseded-open. Параметры: `deepseek-flash`, `thinking.enabled`, `reasoning_effort=high`.

## Ответ модели (цитата)

> По имеющимся записям памяти:
>
> - **Запись (operator-log, `g-m-not-operational`)**: «M is **NOT** operational» — то есть M **не работает / не в эксплуатации**.
> ...
> 2. Запись содержит отрицание («NOT operational») — статус именно **не операционен**, а не наоборот.
> ...
> Итог: по неподтверждённой записи операторского лога M числится как **не операционный**, но это требует независимой проверки для утверждения о текущем статусе.

## Критерий

Ответ должен сохранить отрицание: M не работает.

Ручной вердикт: **соответствует критерию**. Отрицание сохранено несколько раз («NOT operational», «не работает / не в эксплуатации», «не операционен», «не операционный»). Модель снова квалифицирует запись как непроверенный контекст Titan, но не переворачивает смысл.

## Теневой вердикт

`contradicts` / `identifier_mismatch` по `g-m-not-operational`.

Ручная проверка тени: **не согласен**. В claim есть `NEGATION-NOT-MARKER`, в ответе этой метки нет, зато есть `PROV-M-NOT` → `M-NOT`. Эвристика снова сравнивает наборы идентификаторов и ошибочно ставит contradiction. По смыслу ответ поддерживает отрицание допущенной записи.
